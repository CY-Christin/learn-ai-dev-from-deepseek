# 01 · 这个仓库有多不寻常

先建立基本盘。以下数据来自 `git clone --filter=blob:none` 后对完整提交历史的统计（2026-08-15，master 分支）。

!!! note "口径与更新"
    本章数字按 author date 统计，快照点为 commit `99151657`，即 08-15 clone 时拿到的 HEAD（事后发现它是一条 08-19 才合入 master 的分支提交）。按该 commit 重算总数为 12,374，原稿的 12,293 来自更早一次统计，派生数字也随之微调（`codex/*` 分支 203 → 204，创始人占比 43% → 42%），第 09 章用的是重算后的数。长寿分支在快照之后合入时会把 author date 更早的 commit 补进历史，所以按日、按月的数字会随时间上修。三周后的增量数据，以及本章两条"AI 参与证据"后来的退场，见[第 09 章](09-规则的改写.md)。

## 速度

- 首个 commit：2026-06-10。到 8 月中旬，**64 天，12,293 个 commit**。
- 7 月单月 8,273 个；8 月 11 日单日 473 个。日均约 200。
- 提交时间分布：下午到凌晨都是高峰，0 点到 2 点仍有约 1,500 个提交。

这个节奏不可能是人类手写。它是"人定方向 + agent 执行 + 门禁验收"模式跑出来的吞吐量。

## 谁在写

- Tianyi Cui 一人 5,235 个 commit，占 43%。开仓头两天内从零搭完 monorepo、CI 矩阵、最严格 TypeScript 配置、100% 每文件覆盖率门禁——**先把质量闸门焊死，再让 agent 狂奔**。
- 前 20 位作者覆盖了绝大多数提交。仓库不接受外部 PR（CONTRIBUTING.md 明说），参与者全部受控。

## AI 参与的直接证据

不需要猜，历史里全是明牌：

- **第一个 commit** 的内容就是：`Initialize repo with README, AGENTS.md, and CLAUDE.md symlink`。项目从第一天就是为 agent 干活设计的，CLAUDE.md 是指向 AGENTS.md 的软链接。
- 合并记录里有 **203 个 `codex/*` 分支**、若干 `claude/*` 分支——DeepSeek 开发自家 agent 框架，用的是 Codex 和 Claude Code。
- 大量形如 `fix: address codex review round 1/2/3` 的提交：agent 写完，另一个 agent 审，按轮次修。全历史有 639 条提交消息提到 review。
- 建仓第二天的 commit 里就有 "Fix schema-DSL findings from the second Codex review"。

这两条证据在 8 月下旬都退场了，见第 09 章。

## 提交构成

Conventional commits 前缀统计：

| 前缀 | 数量 |
|---|---|
| fix | 2,251 |
| docs | 1,356 |
| test | 950 |
| feat | 687 |
| refactor | 447 |

两个信号：**fix 是 feat 的三倍多**——快速迭代必然伴随大量修补，他们不掩饰这一点；**docs + test 合计超过 fix**——文档和测试不是附属品，是被门禁强制的一等产出（100% 覆盖率门禁、文档字数预算门禁、双语配对门禁都会把不达标的提交直接拒掉）。

## 一个值得记住的画面

这个仓库同时是三样东西：一个 agent 框架产品、一份 AI 驱动开发的完整实验记录、以及一套自我修订的方法论文档。产品本身讲"everything is a plugin"，而它的开发过程讲的是另一句话——**everything is distilled**：每条规则、每个技能、每篇文档，都能在 git 历史里找到它从哪个坑里长出来。

下一章从他们最独特的发明开始：Agent Notes。（第一次发布之后的三周里，这个仓库的节奏、参与者和规则都变了不少，见第 09 章。）
